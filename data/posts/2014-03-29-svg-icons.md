Responsive design is a popular topic. Screens have long gone beyond standard resolutions, and websites can be viewed on both palm-sized devices and large monitors. The site should look equally good regardless of device size and pixel density.
There are many different techniques and technologies for adapting design and content. Vector graphics, SVG, in my opinion, are one of the most interesting topics in this direction.<!--more-->

SVG graphics are convenient to use for icons; they will not look soapy on retina devices and can be stretched without losing quality.

<h2 id="create-icons">Draw it yourself</h2>

To create your own set of icons you will need a vector editor:

- <a href="http://www.adobe.com/ru/products/illustrator.html">Adobe Illustrator</a> - in my opinion, the best. RUB 599/month as part of a Creative Cloud subscription;
- <a href="http://www.inkscape.org/en/">Inkscape</a> - free and not very convenient;
- <a href="http://www.bohemiancoding.com/sketch/">Sketch</a> - for Mac OS, $79.99. Has some problems with vectorization of strokes, but generally quite convenient.

<h2 id="optimize">Optimization</h2>

The finished SVG file usually contains a lot of unnecessary stuff, but at the same time lends itself well to optimization. Unnecessary attributes, spaces and hyphens are removed from the code, and the number of characters after the period in numbers is reduced. File weight is reduced by 30-50%.
Optimization tools, for example:

* <a href="http://petercollingridge.appspot.com/svg-optimiser">petercollingridge.appspot.com/svg-optimiser</a>
* <a href="https://github.com/svg/svgo">github.com/svg/svgo</a>
* <a href="https://github.com/sindresorhus/grunt-svgmin">github.com/sindresorhus/grunt-svgmin</a>

<b>grunt-svgmin</b> is a task for Grunt using <b>svgo</b>. In this case, the files themselves will be taken from the source folder, optimized and stored in the results folder. Very convenient.

<h2 id="sprite-or-font">Sprite or icon font?</h2>

Font is a convenient alternative to sprite. There is no need to bother with the grid and arrangement of icons; it is convenient to add new symbols, although this requires additional tools.

Using the font, you can create not only single-color icons, but also <a href="https://codepen.io/parkerbennett/pen/tIzho">multi-colored</a>.

You can make your own font, for example, on the website <a href="http://icomoon.io/app/">icomoon.io/app/</a>. Approximate sequence of actions:

<ol>
<li>Select icons from the set and/or upload your own.</li>
<li>Click the Font button below.</li>
<li>At this step, you can reassign symbols for icons or immediately download the resulting font.</li></ol>

Along with the font in four formats (.woff, .svg, .ttf, .eot), CSS and a demo file are downloaded.

Embedded fonts work even in IE 8, but have unexpected support issues in some modern browsers.
Opera Mini does not support custom fonts at all, Firefox requires spells for the server where the font is located (solved using base64), Chrome can unload the font if you leave the tab open for a long time:

<img src="//img-fotki.yandex.ru/get/9810/5091629.9d/0_7fdcb_6f0d8340_M.png" alt="">

also in Chrome on Windows7, a page with embedded fonts may <a href="https://code.google.com/p/chromium/issues/detail?id=116739">freeze when opening</a>, and in some other browsers, instead of icons, there can be anything, for example, emojis (the problem was described in the article by Chris Coher <a href="http://css-tricks.com/svg-sprites-use-better-icon-fonts/">Icon System with SVG Sprites</a>).

<a href="http://css-tricks.com">CSS-tricks</a>, by the way, very actively uses SVG in its new design, and the developers of <a href="https://codepen.io/">Codepen</a> in the new editor design abandoned the use of icon fonts in favor of SVG.</i>

Another article in support of SVG: <a href="http://ianfeather.co.uk/ten-reasons-we-switched-from-an-icon-font-to-svg/">Ten reasons we switched from an icon font to SVG</a>.

Despite the ease of use, font support problems currently force us to opt for SVG icons.

I would like to hope that in the future embedded fonts will be better supported.

What are the different ways to insert SVG into a page?

<h2 id="sprite">Sprite</h2>


```css
.icon {
  background-image: url(your.svg);
}
```
<b>Pros:</b>

- short readable code;
- the image is cached;
- good browser support: all except <s>Opera on Presto and</s> old IE.

<b>Cons: </b>

- request to the server;
- in older Operas, background SVG support is strange: problems may arise when adding a frame to an element with an SVG background, and in Opera Mini only backgrounds without viewBox work;
- icons in the sprite are not available for page styles;
- large sprites can cause performance problems.

<h2 id="base64-in-data-uri">Base64 in data URI</h2>

```css
.icon {
  background-image: url(data:image/svg+xml;base64,PHN2ZyB4bWxucz0iaHR0cDovL...);
}
```

<b>Pros:</b>

- no request to the server.
- good browser support: all except <s>Opera on Presto and</s> old IE.

<b>Cons: </b>

- the image is not cached and is rendered anew each time;
- long line in CSS;
- unreadable: it is not clear from the code what it contains;
- the encoded image may weigh more than the original one;
- additional tools are needed for encoding/decoding;
- icons are not available for page styles.

<h2 id="svg-in-data-uri">SVG in data URI</h2>

```css
.icon {
  background-image: url("data:image/svg+xml;utf8,&lt;svg xmlns=...");
}
```
<b>Pros:</b>

- no request to the server;
- relatively readable code (can be read or edited);
- does not require decoding;
- supported by all modern browsers if <a href="https://yoksel.github.io/url-encoder/">SVG encoded</a>.

<b>Cons: </b>

- not cached;
- long line in CSS;
- icons are not available for page styles;
- <s>only supported by Webkit browsers.</s>

<h2 id="reuse">Use (reusing SVG elements)</h2>

```html
<svg width="48px" height="48px" viewbox="0 0 32 32">
  <use xlink:href='#d'/>
</svg>
```

<b>Pros:</b>

- readable code;
- you can add <code>title</code> and <code>desc</code> to pictures;
- symbols are available for page styles. You can also set icons to <code>fill="currentColor"</code>, and they will be colored along with the text.

<b>Cons: </b>

- inserted directly into HTML. Elements must be declared at the top of the page in an inline SVG before they can be used.
There may be a more elegant way to connect the element library, I couldn't find it.

<h2 id="font">Font</h2>

```css
.icon {
  content: "\6c";
  font-family: 'icomoon';
}
```

<b>Pros:</b>

- convenient code;
- the only method supported in IE8 without fallbacks;
- icons are available for page styles, and will be painted along with the text.

<b>Cons: </b>

- if the font has not loaded (not yet loaded, not loaded at all, or has already been unloaded), instead of icons there will be letters or Unicode symbols or nothing.

<h2 id="fallback">Displaying icons in browsers without SVG support</h2>

At the moment, the most convenient and reliable way to insert is in the form of a sprite.

To replace images in IE8 and older, you can use the method with multiple backgrounds:


```css
.icon {
  background-image: url(your.png); /* PNG для IE6-8 */
  background-image: url(your.svg), none;
}
```

For old Operas you can use the following selector:


```css
doesnotexist:-o-prefocus,
.icon {
  background-image: url(your.png);
}
```

In this way, you can ensure that the icons for users with different browsers look approximately the same.

Of the existing methods for inserting icons, I like font the most. It would be perfect if it weren't for the support issues.
I don’t like <code>Use</code> for mixing markup and design, although I’m pleased with the accessibility for CSS and the ability to add <code>title</code> and <code>desc</code>.
There is another very good, but poorly supported method, but this is a topic for <a href="/svg-stacks/">a separate post</a>.
