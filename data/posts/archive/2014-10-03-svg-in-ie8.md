After running into the same pitfalls once again, I finally decided to describe the essence of the problem and the ways to solve it. The topic is how to make old browsers understand and display SVG elements — at least as an empty block of given dimensions.<!--more-->

Suppose you need SVG icons. You plan to recolor them on hover or interact with them in some other way, so as the insertion method you choose not <code>background-image</code> but <code>use</code>.

It is assumed that you have prepared an icon library and inserted it into the page.

For example, let's take this symbol:

```html
<symbol id="s-heart" viewBox="0 0 100 100">
  <path d="M100 34.976c0 8.434-3.635 16.019-9.423 21.274h0.048l-31.25 31.25c-3.125 3.125-6.25 6.25-9.375 6.25s-6.25-3.125-9.375-6.25l-31.202-31.25c-5.788-5.255-9.423-12.84-9.423-21.274 0-15.865 12.861-28.726 28.726-28.726 8.434 0 16.019 3.635 21.274 9.423 5.255-5.788 12.84-9.423 21.274-9.423 15.865 0 28.726 12.861 28.726 28.726z" fill="crimson"/>
</symbol>
```

Now the icon needs to be inserted in the right place. First of all we write this:

```html
<svg>
  <use xlink:href="#s-heart"/>
</svg>
```

<i>Yes, I know that the tag should specify the namespace for all browsers to understand the tag correctly. But so far I haven't encountered problems displaying this construct, and I've always wondered: what if you don't specify it — what breaks, and where? Do we always have to append such a long tail to such a short tag?</i>

The <code>viewBox</code> is already set in the symbol, so it doesn't need to be specified in the <code>svg</code> when inserting into the page; you only need to set the icon's dimensions.

Setting the dimensions:


```css
SVG {
  width: 100px;
  height: 100px;
}
```

The construct works in all browsers that support SVG.

Now we need to take care of old browsers and add a background PNG to the icon. We write something like:


```css
SVG {
  width: 100px;
  height: 100px;
  background: url(heart.png);
}
```

<i>Usually the background image is set only for old browsers, for example via the class <code>.lt-ie9 SVG</code>, but here I left this moment out for simplicity.</i>

We check in IE8 and see that nothing works, and for several reasons at once:

1. The SVG element doesn't exist from IE8's point of view. To make the browser begin to suspect its existence, you need to add the namespace it belongs to into the <code>svg</code> tag: <code>xmlns="http://www.w3.org/2000/svg"</code>.
2. IE8 doesn't understand selecting an SVG element by tag — only by class.
3. The SVG element absolutely needs <code>display: block</code> or <code>display: inline-block</code> added.

Fixing the code, we get this:

```html
<!-- добавлены класс и пространство имен -->
<svg xmlns="http://www.w3.org/2000/svg" class="svg-icon">
  <use xlink:href="#s-heart"/>
</svg>
```


```css
/* стили перенесены на класс, добавлен display: inline-block */
.svg-icon {
  display: inline-block;
  width: 100px;
  height: 100px;
  background: url(heart.png);
}
```

The SVG element appeared in IE8, only it will show a background image instead of vector content.

<i>Of course you could skip the fuss, wrap the SVG in a <code>span</code> tag, for example, and set the background and dimensions on it, but why, when you can manage without extra markup?</i>

It would seem we've got an SVG with a fallback in IE8 and everything works as it should, but the problems don't end there. If the page contains HTML5 tags, the layout can fall apart if the elements inside SVG don't have paired closing tags.

Html5shiv.js can't do its job correctly, because of which the HTML5 tags can't become block-level.

There are two solutions here:

1. Add an explicit <code>display: block</code> declaration for HTML5 tags to your CSS.
2. Close all SVG tags when inserting them into the page:

For example, there's a symbol containing a <code>path</code>:

```html
<symbol id="s-heart" viewBox="0 0 100 100">
  <path d="M100 34.976c0 ... 28.726 28.726z"/>
</symbol>
```

Add the closing tag:

```html
<symbol id="s-heart" viewBox="0 0 100 100">
  <path d="M100 34.976c0 ... 28.726 28.726z"></path>
</symbol>
```

The same has to be done for all <code>use</code> tags:

```html
<svg xmlns="http://www.w3.org/2000/svg" class="svg-icon">
  <use xlink:href="#s-heart"></use>
</svg>
```

<a href="https://codepen.io/yoksel/pen/CujKg">The corrected markup</a> will work correctly in all browsers.

I hope this article saves someone time in the future, because known pitfalls can be sidestepped without falling into them. May the force of SVG be with you!
