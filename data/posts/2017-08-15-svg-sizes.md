Controlling sizes is an important topic, and to make the most of SVG's capabilities you need to understand well how it all works.

<!--more-->
<a href="http://www.w3.org/TR/SVG/coords.html">Specification</a>.

<h2 id="viewport">Viewport</h2>

The contents of an SVG element are drawn on an infinite canvas and can be of any size at all, but the visible part of the canvas corresponds to the SVG element's size. This drawing area is called the `viewport`.

SVG lets you control both the viewport's size and the content's behavior relative to it: it can be clipped or shown fully, it can stretch losing its proportions or try to fit entirely, even if empty margins appear. This behavior can be controlled with attributes.

If you simply put an SVG on a page without giving it any sizes, it will be displayed at 300px by 150px, and whatever doesn't fit will be clipped:

<h2 id="width-height">Width and height</h2>

An element's width and height can be controlled with the standard `width` and `height` properties:

```html
<svg width="350" height="200">
  ...
</svg>
```

They can be set both as attributes and in CSS:


```css
.mysvg {
  width: 350px;
  height: 200px;
}
```

For pixel sizes set in attributes, the units don't have to be specified.

Drag the sliders and you'll see that changing width and height affects only the viewport, not the content, because the content is drawn on an infinite canvas and it's unknown what size area needs to be resized.

<h2 id="viewBox">viewBox</h2>

An `iframe` resizes similarly without changing its content's size, but in SVG's case this behavior can be changed by defining the area's size with the `viewBox` property:

```html
<svg width="350" height="200"
    viewBox="0 0 180 180">
  ...
</svg>
```

The first two values are the X and Y coordinates of the top left corner of the displayed area, the last two are width and height. `viewBox` can only be set as an attribute.

Now try changing the sizes and you'll see the content resize to fit entirely.

This behavior can become a problem: if icon sizes are set in styles and the styles fail to load, the page can turn into a parade of giant SVG icons. To prevent this, always explicitly set width and height in the SVG attributes; they can easily be overridden in CSS later.

<h2 id="preserveAspectRatio">preserveAspectRatio</h2>

As we saw in the example above, if an SVG has sizes and a `viewBox`, the content will shrink and stretch while keeping its proportions in order to fit entirely, but this behavior can also be controlled — with the `preserveAspectRatio` property (it can only be set as an attribute).

For example, with the value `none` you can specify that proportions don't have to be kept:

```html
<svg width="350" height="200"
    viewBox="0 0 180 180"
    preserveAspectRatio="none"
    >
  ...
</svg>
```

<p data-height="450" data-theme-id="4974" data-slug-hash="xLdQqX" data-default-tab="result" data-user="yoksel" data-embed-version="2" data-pen-title="SVG preserveAspectRatio='none'" class="codepen">See the Pen <a href="https://codepen.io/yoksel/pen/xLdQqX/">SVG preserveAspectRatio='none'</a> by yoksel (<a href="https://codepen.io/yoksel">@yoksel</a>) on <a href="https://codepen.io">CodePen</a>.</p>
<script async src="https://production-assets.codepen.io/assets/embed/ei.js"></script>

An SVG with `viewBox` and `preserveAspectRatio='none'` behaves very much like an `img`: when the size changes, the content scales to the viewport size without keeping proportions.

`none` is useful for fluid backgrounds:

<script async src="https://production-assets.codepen.io/assets/embed/ei.js"></script>

The other `preserveAspectRatio` values consist of two parts: the first sets the alignment, the second — the element's behavior relative to the viewport.

Alignment is set with a single value defining the position vertically and horizontally, for example: `xMaxYMin`. For both axes you can set the position at the start, the middle and the end:

`xMin`, `YMin` — at the start of the axis
`xMid`, `YMid` — in the middle
`xMax`, `YMax` — at the end

These values can be combined in any combination, but the order must be kept: the X value always comes first, the Y value second. The Y value is always written with a capital letter.

The element's behavior is defined by the second part of `preserveAspectRatio`. Possible values:

`meet` — the content tries to fit entirely (like a background with `background-size: contain`)
`slice` — the content fills the whole visible area (like `background-size: cover`: whatever doesn't fit gets clipped)

It's important to remember that `preserveAspectRatio` doesn't work without `viewBox`. `viewBox` defines the area that must be scaled, `preserveAspectRatio` defines exactly how it should do that.

You also need to understand that `preserveAspectRatio` kicks in when the viewport and viewBox have different aspect ratios. If the aspect ratios match and the content fits without margins, `preserveAspectRatio` won't do anything (in that case it's simply not needed).

For using SVG as icons, `viewBox` and sizes are enough, but if you plan to do something more complex, it makes sense to figure out units of measurement and the coordinate system.

<h2 id="units">Units of measurement</h2>

Inside SVG you can use `em`, `ex`, `px`, `pt`, `pc`, `cm`, `mm`, `in`, percentages, as well as coordinate system units (user space units). Coordinate system units correspond to pixels, so for pixel values the units don't need to be specified.

<h2 id="coordinates">Coordinate systems</h2>

An SVG document has two coordinate systems:

1. The coordinate system of the drawing area — <b>viewport space</b>.
2. The coordinate system of the content — <b>user space</b>.

The viewport's coordinate system starts from the viewport's top left corner; the content's coordinate system starts from the viewBox's top left edge.

By default the content's coordinate system corresponds to the viewport's coordinate system, and the content's units correspond to the viewport's units, but when transformations or <code>viewBox</code> are used, the whole coordinate system with its units is scaled, that is, pixels from <i>user space</i> are no longer equal to pixels from <i>viewport space</i>.

```html

  stroke="black" stroke-width="1"
  vector-effect="non-scaling-stroke"/>
```
