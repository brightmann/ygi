CSS has [mathematical functions](https://www.w3.org/TR/css-values-4/#calc-notation), four of them in total: `min()`, `max()`, `clamp()` and `calc()`.

Some kind of math also exists in preprocessors; for example, SCSS has `min()`, `max()` and `clamp()`, Less has `min()` and `max()`, but there are a couple of significant differences. First, in preprocessors everything is calculated once at compile time, and the final file always contains fixed values. And second, preprocessor functions can't combine different units of measurement.
<!--more-->

For example, you can't make a pixel-based value that depends on viewport units. This example won't work (it's SCSS):

```css
$base-font-size: 16px;

BODY {
  font-size: $base-font-size + 2vw;
}
```

The compiler will complain about incompatible units.

But if you move the calculations into `calc()`, everything will work:

```css
$base-font-size: 16px;

BODY {
  font-size: calc(#{$base-font-size} + 2vw);
}
```

`calc()` can add pixels and viewport units. This makes it possible to have a fluid font size that depends on the browser window width. Preprocessors can't do that.

So the main advantage of mathematical functions in CSS is the dynamism of values thanks to the ability to combine absolute and relative [units of measurement](/size-units/).

It's also important to remember that when using preprocessors, CSS functions can conflict with preprocessor ones. For example, if you write this in SCSS or Less:

```css
width: min(350px, 50%);
```

the compiler will complain about incompatible units, because the preprocessor's function will kick in.

To keep preprocessors from trying to execute CSS functions during compilation, **SCSS** suggests writing the function name with a capital letter:

```css
width: Min(350px, 50%);
```

You can read more about this in Ana Tudor's article [When Sass and New CSS Features Collide](https://css-tricks.com/when-sass-and-new-css-features-collide/).

In **LESS**, [wrapping in quotes](http://lesscss.org/#escaping) helps:

```css
width: ~"min(350px, 50%)";
```

or compiling with [the option](http://lesscss.org/usage/#less-options-math) `math` set to `strict`.

<h2 id="min-max">min(), max()</h2>

The `min()` function returns the smallest of the passed values, `max()` — the largest. When using percentages or [relative units](/size-units/#relative-units), the chosen value will be dynamic and will depend on external conditions. For example:

```css
width: min(350px, 50%);
```

At first glance, `min()` and `max()` don't do anything interesting, but think about it: how many places in CSS let you control the *range* of values?

It's available only for width and height:

* `width`, `min-width`, `max-width`
* `height`, `min-height`, `max-height`

and their writing-mode-bound counterparts:

* `inline-size`, `min-inline-size`, `max-inline-size`
* `block-size`, `min-block-size`, `max-block-size`

We don't have, for example, `max-font-size` or `min-border-width`, but thanks to mathematical functions you can add smart dynamics to practically any value. For example, to font size:

```css
font-size: max(5vw, 20px);
```

If you tried to implement something like this in JS, you'd have to track window resizing, get the computed value, and when it passed the given threshold, pin the value at a certain level. With `min()` and `max()` the browser does everything itself: it tracks value changes and, when needed, pins them — we just need to pick a function and set the range of values.

This will work in all properties that use sizes, including shadows, gradients and so on. An example with `box-shadow`:


Experimenting with `min()` and `max()`, you may notice that they let you control either the minimum value or the maximum, but not both at once. Yet it seems perfectly logical to want, for example, a font size that grows within a range from a minimum value to a maximum and doesn't go beyond them.

For that there's another function:

<h2 id="clamp">clamp()</h2>

It combines `min()` and `max()`. The function takes parameters:

```css
clamp(MIN, VAL, MAX)
```

And computes the value like this:

```css
max(MIN, min(VAL, MAX)))
```

The easiest way to understand it is to think of the middle value (`VAL`) as the preferred one, constrained by minimum and maximum values. For example, this code

```css
font-size: clamp(20px, 5vw, 40px);
```

describes the following behavior: the font size is `5vw`, but no less than `20px` and no more than `40px`. Stretch the demo to see how it works:

The previous functions are fairly simple compared to `calc()`, the most powerful and interesting one.

<h2 id="calc">calc()</h2>

The function lets you perform mathematical operations:

* addition
* subtraction
* multiplication
* division

Unlike preprocessor calculations, `calc()` lets you combine any compatible values. For example, you can subtract pixels from percentages:

```css
width: calc(100% - 20px);
```

Preprocessors can't do that, because at CSS compile time it's unknown what `100%` equals, but the browser has that data, so it can take `100%`, convert it to pixels and subtract `20px` from it. On top of that, the browser will recalculate the value if the element's width changes.

Inside `calc()` you can use custom properties, and that makes calculations in CSS much more powerful than preprocessor ones. For example, with `calc()` and custom properties you can build a simple color scheme generator without any scripts:

When you click a color, the value of a CSS variable changes in the CSS, and the whole palette is recalculated.

The hue calculation (`hue` from HSL) is done like this:

```css
--palette-hue-2: calc(var(--palette-hue) + var(--palette-step-1));
```

And then the hue is used to form a color in HSL format:

```css
background: hsl(var(--palette-hue), var(--base-sat), var(--base-lght));
```

Of course, things like this are more convenient and logical to do in JS; the demo simply shows that CSS is powerful enough to be capable of it.

<h3 id="examples">Usage examples</h3>

<h4>Preserving the logic of calculations</h4>

For example, if you need a width of 1/12 of the total, you can compute the value and write it into the styles:

```css
.block {
  width: 8.33%;
}
```

But it's unclear what this number is. It becomes a bit clearer if you put the calculation logic next to it in a comment:

```css
.block {
  width: 8.33%; /* 100% / 12 */
}
```

And if you use `calc()`, you can make the mathematical expression itself the value:

```css
.block {
  width: calc(100% / 12);
}
```

This way it's immediately clear that the element takes up 1/12 of its parent's width, and there's no need to keep comments up to date.

<h4>Controlling element sizes</h4>

For example, there's a card with an image, and the image shrinks to the width of the text column:

```css
.card {
  min-width: 300px;
  max-width: 400px;
  padding: 1rem;
}

.card__img {
  width: 100%;
}
```

You can improve the code a bit more using custom properties:

```css
.card {
  --padding: 1rem;

  min-width: 300px;
  max-width: 400px;
  padding: var(--padding);
}

.card__img {
  width: calc(100% + var(--padding) * 2);
  margin-left: calc(var(--padding) * -1);
}
```

This way the calculation logic is preserved, `1rem` becomes not a magic number but a named variable, and the code itself makes it clear that the image width grows by two paddings and then shifts left by one. You can roughly understand what this code does without even looking at the page in the browser.

This is also useful for inputs. Suppose you want an input to stretch to its parent's full width, leaving 40 pixels on the right. A fixed-width variant doesn't suit responsive design. If you just set width to 100% plus a margin, the block will stretch to full width and won't shrink. `calc()` handles this task beautifully:

```css
.input {
  width: calc(100% - 40px);
}
```

```css
  line-height: calc(1.2rem + .5vw);
```

<h4>Controlling background sizes</h4>

With `calc()` you can set a background image's size by combining fixed units and percentages. For example, so the background is always offset from the edges by a certain value:

```css
DIV {
  --offset: 1rem;
  --bg-size: calc(100% - var(--offset) * 2);

  /* Colored gradient */
  background: linear-gradient(45deg, crimson, 20%, gold, 80%, turquoise) no-repeat;
  /* Background size */
  background-size: var(--bg-size) var(--bg-size);
  /* Offset from the element's edge */
  background-position: var(--offset) var(--offset);
}
```

```css
      turquoise 0, turquoise calc(50% + var(--line-witdh) / 2),
      transparent 0
    );
}
```

<h4>Computing colors and gradient stops</h4>

Sometimes you need a striped gradient for experiments. To avoid computing the parameters by hand, you can calculate them with `calc()` based on custom properties. Here's how the parameters are set:

```css
--steps: 9;
--hue-step: calc(360deg / var(--steps));
--line-width: 1rem;
```

And here's how the hue is then calculated:

```css
hsl(calc(var(--hue-step) * 2), 100%, 63%)
```
And the color stop:

```css
calc(var(--line-width) * 7)
```

By editing the variables you can change the gradient's parameters without having to recalculate the steps manually or rewrite the whole gradient.

Admittedly, with such automatic hue calculation the colors may turn out not very pretty, but it's quite good enough for experiments.

The range of uses for `cacl()` is much wider than these examples. In some cases, if values don't need to change dynamically, preprocessors can handle similar tasks too, but if they do — for example, when custom properties or the window size change — you can't do without `calc()`.

<h3 id="nuances">Nuances</h3>

When using `calc()` you need to remember a few subtleties:

* the arithmetic operator must always be surrounded by spaces so the browser can parse the expression correctly. For example, `width: calc(100% -50px)` won't work; the correct way is: `width: calc(100% - 50px)`. For multiplication and division this requirement isn't mandatory, but it's better to always add spaces to keep the code consistent and easy to read;

* you can't divide by zero; the result will be an error;

* `calc()` can only perform calculations for compatible units. For example, you can add pixels to percentages or viewport units, degrees to radians, and subtract milliseconds from seconds, but you expectedly can't add seconds to pixels or degrees to viewport units, because it's unclear what units the result is expected in.

  I had a slightly crazy idea to tie gradient degrees to the viewport width (and rotate the gradient by stretching the browser window), but I couldn't figure out how to implement it, and I'm not sure it's possible at all without JS;

* calculations in media queries are supported only for identical units: pixels can be added to pixels, rems to rems. You can't add pixels to rems inside a media query. Custom properties don't work inside media queries at all, and so no calculations with them are possible ([demo with calc() in @media](https://codepen.io/yoksel/full/bGpQXdb)). For more complex constructs you can try using [logical operations](https://css-tricks.com/logic-in-media-queries/).

<h3 id="restrictions">A bright future?</h3>

The [specification](https://www.w3.org/TR/css-values-4/#calc-notation) has an interesting bit: it states that inside `calc()` you can use attribute contents as values, and in general attributes can be used as [values of CSS properties](https://www.w3.org/TR/css-values-4/#attr-notation).

What distinguishes this from the ordinary use of `attr()` as [pseudo-element content](/content) is the specification of the content type:

```css
/* HTML
<div data-color="#FC9">...</div>
*/

background: attr(data-color color, orange);
```

Or of units:

```css
/* HTML
<div data-length="300">...</div>
*/

width: attr(data-length px, 200px);
```

The value after the comma is a fallback, in case the attribute value can't be obtained or parsed.

At first this construct seemed strange to me: why put data into attributes and then also type them in CSS, when you can put what you need straight into custom properties?

For example:

```css
/* HTML
<div style="--width: 100px"></div>
*/

DIV {
  width: var(--width);
  height: 50px;
  background: gold;
}
```

But [on Twitter](https://twitter.com/yoksel/status/1304025539120902145) people quickly threw me examples of when it would be really convenient. For example, getting sizes from attributes would be convenient for making responsive images and frames. I managed to make a [responsive video](/adaptive-video-with-css-math) using custom properties, but that requires duplicating the sizes in inline styles. If values could be read from attributes, you could do without the duplication.

At the time of writing this is not supported by [any browser](https://caniuse.com/mdn-css_types_attr_type-or-unit), but there's some hope that one day it will work, because this use of attributes is described in the specification of a property that would help control the aspect ratio: [aspect-ratio](https://drafts.csswg.org/css-sizing-4/#ratios). It has this example:

```css
/* HTML
<iframe
  src="https://www.youtube.com/embed/0Gr1XSyxZy0"
  width=560
  height=315>
*/

@supports (aspect-ratio: attr(width number) / 1) {
  iframe {
    aspect-ratio: attr(width number) / attr(height number);
    width: 100%;
    height: auto;
  }
}
```

And that would be really cool, because it would free developers from having to build [strange constructions](https://css-tricks.com/fluid-width-video/) to solve the same task. You can read about `aspect-ratio` in Rachel Andrew's article [Designing An Aspect Ratio Unit For CSS](https://www.smashingmagazine.com/2019/03/aspect-ratio-unit-css/).

Also, not so long ago other mathematical functions [were added](https://css-live.ru/vecssti-s-polej/novye-matematicheskie-funkcii-v-module-edinic-i-znachenij-css-4-urovnya-eshhe-odin-shag-k-polnocennomu-programmirovaniyu-na-css.html) to the [drafts](https://drafts.csswg.org/css-values-4/#round-func), for example `mod()`, `round()`, `sin()` and many others. This is a very fresh addition; the new functions aren't supported anywhere yet.

<h2 id="support">Browser support</h2>

`min()`, `max()`, `clamp()` and `calc()` are supported in [most modern browsers](https://caniuse.com/css-math-functions), their support roughly matching that of [custom properties](https://caniuse.com/css-variables). Neither works in IE11.

If you need to check support for the functions and custom properties, you can use `@supports` (also keeping in mind [its browser support](https://caniuse.com/css-featurequeries)):

```css
@supports (--color: pink) {
  ...
}

@supports (width: min(10px, 20px)) {
  ...
}
```
