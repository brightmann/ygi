SVG is a vector image format based on XML.

Specification: <a href="http://www.w3.org/TR/SVG/">w3.org/TR/SVG</a>

SVG has a lot of advantages over raster images:<!--more-->

- vector images are scaled without loss of quality and are better displayed on retina devices;
- SVG, as a rule, weighs slightly less than the PNG version of the same image;
- the contents of the picture are described in XML, the SVG file can be opened in a text editor and see human-readable code;
- therefore, an SVG image can not only be drawn in a vector editor, but also written by hand;<!--more-->
- An SVG file is always the source. Unlike raster graphics, editing it does not require the original PSD file, the contents of the file are not glued into one layer, so you can always simply open and edit it. However, if the file also contains styles and scripts, it is better not to do this, because the contents will be overwritten;
- inside an SVG file you can describe shadows and gradients, and they can be used not only inside this file, but can also be applied to external elements (does not work everywhere yet);
- CSS and JavaScript can be inside the file.

SVG is well supported by all modern browsers and can already be used by providing PNG versions for older browsers.

It's well suited for use in responsive design because it stretches and shrinks losslessly, weighs less, and doesn't look blurry on high-pixel-density devices. Here, for example, is a screenshot from a modern smartphone:

<img src="//img-fotki.yandex.ru/get/9809/5091629.9d/0_7fa35_27e932b6_L.jpg" alt="">

You can clearly see that SVG (bottom) looks much better than PNG (above) under these conditions. So if you set yourself the task of making a website that looks good on any device, SVG will be very useful.

You can already find quite a few sites with ready-made SVG graphics, for example:

* <s><a href="http://iconmelon.com/">iconmelon.com</a></s>
* <a href="http://icomoon.io/app/#/select">icomoon.io</a>
* <a href="http://www.flaticon.com/">flaticon.com</a>

Basically, these are icon sets.

You can use the pictures as is, or you can recolor them, combine them into a stack, a sprite, or make a font.

SVG can be inserted into a page in several ways. They are supported differently by browsers and provide different capabilities.

<h2>Display methods in older browsers:</h2>

<h3>1. Hack for an element with a background:</h3>

```css
DIV {
  background-image: url(your.png); /* PNG для IE6-8 */
  background-image: url(your.svg), none;
}
```

The second line will work in browsers that support CSS3, older ones will ignore it and show the PNG from the first line.

<h3>2. Method with <code>image</code></h3>

Modern browsers will select the <code>xlink:href</code> attribute and show the SVG, older browsers will select the <code>src</code> attribute and show the raster version:

```html
<svg width="200px" height="200px">
  <image xlink:href="your.svg"
    src="your.png"
    width="200px" height="200px"/>
</svg>
```

The method was found here: <a href="http://lynn.ru/examples/svg/">lynn.ru/examples/svg/</a>.
Chris Coyer has an article about this method <a href="http://css-tricks.com/svg-fallbacks/">Svg fallbacks</a>, in which he analyzes this insertion option and suggests others.

The method works well in IE8 and Opera Mini.
The downside of this method is loading both files into IE9-11, although only SVG will be displayed. There are also problems with display in Opera 12: instead of a picture, sometimes this is loaded:

<img src="//img-fotki.yandex.ru/get/9831/5091629.9d/0_7f9f6_9033810_M.png" alt="SVG in Opera 12">

<h3>3. Modernizr</h3>
Elements containing SVG graphics are wrapped in <code>div.svg</code> (for example).
Then we define SVG support using <a href="http://modernizr.com/">Modernizr</a>, browsers without SVG are defined by the class <code>.no-svg</code>, then a little CSS:

```css
/* Задаем обертке размеры и фон в PNG: */
.no-svg .svg {
  width: 200px;
  height: 200px;
  background: url(your.png); /* PNG-заглушка */
}

/* Скрываем содержимое обертки (иначе будут отображаться
иконки незагрузившихся картинок) */
.no-svg .svg IFRAME,
.no-svg .svg OBJECT,
.no-svg .svg EMBED,
.no-svg .svg IMG {
  display: none;
}
```

The styles will only work in browsers that don't support SVG.

A good solution for IE8 and older, but may have a problem with Opera Mini.
It has partial SVG support, so there won't be a <code>.no-svg</code> selector, nor does it support SVG in CSS backgrounds and Inline Svg, so they won't render.

For IE, you can also use <a href="http://www.paulirish.com/2008/conditional-stylesheets-vs-css-hacks-answer-neither/">this is how to determine the browser version</a>.

<h3>4. :root</h3>
The <code>:root</code> selector will only work in browsers that support CSS3, so it can also be used to filter styles for old and new browsers.

```css
/* По умолчанию показываем PNG: */
.svg {
  width: 200px;
  height: 200px;
  background: url(your.png);
}

/* Контейнеры с SVG скрыты. */
.svg IFRAME,
.svg OBJECT,
.svg EMBED,
.svg IMG {
  display: none;
}

/* Включаем содержимое для браузеров с поддержкой CSS3 */
:root IFRAME,
:root OBJECT,
:root EMBED,
:root IMG {
  display: inline-block;
}
```

Like the previous solution, it is suitable for IE8 and older, but will not help in Opera Mini, because it supports CSS3, so there will be no placeholders for elements with an SVG background and inline SVG.

<h3>5. Solution for Opera on Presto (for example, 12 and Mini)</h3>

In Opera 12, SVG backgrounds can behave strangely, sometimes to the point of extreme behavior. Completely innocent CSS can cause problems with drawing vector backgrounds when scrolling the page. I managed to get this:

Opera Mini has big problems with background SVG, and inline SVG is not supported at all.

Opera Mini and background SVG:

<img src="//img-fotki.yandex.ru/get/9819/5091629.9d/0_7f9f7_19c1f3e9_L.png" alt="">

In this case, you can use a hack that will only work in Opera:


```css
doesnotexist:-o-prefocus, .selector {
  background-image: url(your.png);
}
```

The method uses an opera-specific selector; you can read more about such selectors here: <a href="http://www.opera.com/docs/specs/presto2.12/css/o-vendor/">opera.com/docs/specs/presto2.12/css/o-vendor</a>

<h3>6. Selector only for Opera Mini</h3>

```css
@media all and (-webkit-min-device-pixel-ratio:10000), not all and (-webkit-min-device-pixel-ratio:0) {
  .selector {
    background-image: url(your.png);
  }
}
```
